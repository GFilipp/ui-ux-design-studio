2. NEW AND FREE — RECOMMEND WIRING

a. Lazyweb — reference/inspiration, free. Your biggest gap, most relevant item in this scan.
281k+ real app screens, plus flows and experiments. This is the category Mobbin and Refero
charge for.
Two paths, and the difference matters:
  - Zero setup, no account. Verified live by handshake; returns "Lazyweb Public Discovery"
    with three tools (search, page_tldr, ask_anything). PUBLIC SITE CONTENT ONLY — this is not
    the screen library, despite how it is marketed.
      claude mcp add -s user --transport http lazyweb-public https://www.lazyweb.com/mcp/public
  - Full screen/flow tools. Needs a free bearer token (email code, no payment). Plan affects
    report depth only, per their own docs: "Setup, health, discovery, and MCP tools remain
    available regardless of plan; non-Pro accounts receive partial reports."
      claude mcp add --transport http --scope user lazyweb https://www.lazyweb.com/mcp \
        --header "Authorization: Bearer <token>"
  Caveat: their install path is a curl-pipe-to-bash script. Do not run it. Use the command
  above with a token pulled manually.
  Conflict flagged: a third-party blog claims Lazyweb "is no longer fully free." Lazyweb's own
  docs say otherwise. I followed the vendor doc and verified the free endpoint myself.
  Source: https://www.lazyweb.com/claude.md

b. Figma remote MCP — official, free during beta, on every plan including Starter.
Reads variables, tokens, components, variants, auto-layout. Figma states it will eventually
become a usage-based paid feature.
      claude mcp add -s user --transport http figma https://mcp.figma.com/mcp
      then authenticate via /mcp (OAuth, browser)
  Only worth wiring if design work actually starts in Figma. If the studio composes from code
  registries, this adds tools you will not call.
  Source: https://help.figma.com/hc/en-us/articles/32132100833559

c. Kibo UI — free, no auth, remote. Confirmed endpoint live.
Fills shadcn gaps (tables, kanban, editors, AI chat primitives). Docs note "future premium
features may require API keys."
      claude mcp add -s user kibo-ui -- npx -y mcp-remote https://www.kibo-ui.com/api/mcp/mcp
  Lower priority than Lazyweb: you already have six component sources and one reference source.
  Source: https://www.kibo-ui.com/docs/mcp

4. STRUCTURAL — WORTH MORE THAN ANY SINGLE ADD

The shadcn MCP you already have supports namespaced registries. One server reaches many
libraries via components.json, with no extra MCP process and no extra tool definitions:

  {
    "registries": {
      "@aceternity": "https://ui.aceternity.com/registry/{name}.json"
    }
  }

Then ask for @aceternity/<component>. This is the clean replacement for the stale Aceternity
server, and the same pattern extends to other shadcn-compatible libraries. Verify each
registry URL against its own docs before adding — shadcn's docs teach the mechanism but do not
publish a directory of live third-party registry URLs, so every URL is a per-library check.
  Source: https://ui.shadcn.com/docs/mcp, https://ui.shadcn.com/docs/registry/namespace
